# 系统设计方案

对应开题报告《基于Spring Boot的私人医生预约服务平台设计与实现》，八大模块、二十五个子功能的技术落地方案。

## 一、总体架构

前后端分离架构，三层职责清晰：

```
浏览器（Vue3 + Element Plus + ECharts）
   │  HTTP / JSON / JWT（Authorization: Bearer）
   ▼
Spring Boot 3.3（Controller → Service → Mapper）
   │  MyBatis-Plus（分页插件 + 条件构造器）
   ▼
MySQL 5.7/8.0（15 张表，utf8mb4）
```

- **认证**：登录后签发 JWT（12 小时过期），前端存入 localStorage，每次请求经 Axios 拦截器自动携带。
- **鉴权**：后端 `AuthInterceptor` 解析 Token 写入 ThreadLocal 用户上下文；`@RequireRole` 注解实现 ADMIN / DOCTOR / PATIENT 三类角色的接口级访问控制。
- **审计**：`@LogOperation` 注解 + AOP 切面自动记录关键操作到 `operation_log`（含 IP、耗时、参数脱敏摘要）。
- **接口文档**：Knife4j（OpenAPI3），启动后访问 `/doc.html`。

## 三、核心设计要点

### 1. 号源防超卖

排班表 `schedule` 有 `max_count`（总号源）与 `booked_count`（已约）。预约时执行：

```sql
UPDATE schedule SET booked_count = booked_count + 1
WHERE id = ? AND status = 1 AND booked_count < max_count
```

`UPDATE` 返回 0 行即号源已满，利用数据库行锁保证并发下不超卖；取消预约反向 `-1`。

### 2. 预约状态机

```
0 待派单 ──派单──▶ 1 已派单 ──填写病历──▶ 2 已完成 ──▶ 可评价
   │                  │
   └────── 取消 ──────┴──────▶ 3 已取消（释放号源）
```

- 线上预约选了号源 → 直接「已派单」；未选号源 → 「待派单」池，由管理员/医生分诊。
- 医生停诊 → 级联取消该排班下未完成预约并释放号源（动态管控）。

### 3. 处方-库存闭环（事务）

处方状态机：`0 待缴费 → 1 已缴费 → 2 已发药`，`3 已作废`（发药前可作废）。
发药在 `@Transactional` 中执行：逐明细校验库存 → 扣减 → 写 `medication_stock_log` 出库流水（含前后库存），任一步失败整体回滚，保证药品流转可追溯。

### 4. 资质审核闭环

医生提交材料（`doctor_review` 状态 0 待审核）→ 管理员通过/驳回 → 联动 `doctor_info.audit_status`；
患者端医生列表只展示 `audit_status = 2`（已通过）的医生，杜绝无资质接诊。

### 5. 数据隔离

列表接口按 Token 中的角色过滤：患者仅见自己的预约/病历/处方/评价；医生仅见自己的接诊与排班；管理员见全量。

### 6. 可视化分析

`/api/stats/*` 提供 5 组聚合数据：总览卡片、7 天预约趋势、科室预约分布、医生接诊量 TOP10、药品消耗 TOP10，前端 ECharts 折线/饼图/柱状图呈现。

## 五、安全设计

- 密码 BCrypt 加密存储，接口响应不回传（`@JsonIgnore`）。
- 全部业务接口需 JWT；`/api/auth/login|register|password/reset` 为白名单。
- 操作日志对参数中的密码字段自动脱敏。
- 前端路由守卫 + 后端 `@RequireRole` 双重角色控制。
- 全局异常处理统一返回 `{code, message, data}`，参数校验失败返回具体提示。

## 六、部署形态

- 开发：前端 `npm run dev`（5173，代理 /api 到 8080）+ 后端 `mvn spring-boot:run`。
- 生产：前端 `npm run build` 产物交 Nginx；后端 `mvn package` 生成可执行 jar，`java -jar` 运行。
